# Continue Issue Command

Verifies plan approval and creates a PR with the automated fix.

## Usage

```bash
/continue-issue-reviews <issue-number>
```

**Example:**
```bash
/continue-issue-reviews 42
```

## Prerequisites

1. `/issue-reviews` already run on this issue
2. Plan posted and approved (👍 or "approve" comment)
3. Approver has maintainer/admin permissions

## Implementation

### Step 1: Validate Input

```bash
if [ -z "$1" ]; then
  echo "❌ Error: Issue number required"
  echo "Usage: /continue-issue-reviews <issue-number>"
  exit 1
fi

ISSUE_NUMBER="$1"
```

### Step 2: Get Repository Info

```bash
REMOTE=$(git remote get-url origin)
OWNER=$(echo "$REMOTE" | sed -E 's/.*github\.com[:/]([^/]+).*/\1/')
REPO=$(echo "$REMOTE" | sed -E 's/.*github\.com[:/][^/]+\/([^.]+).*/\1/')
```

### Step 3: Check Approval

Use @lib/approval-checker:

```markdown
Check approval using lib/approval-checker:

1. Get authorized users from GitHub
2. Find plan comment (contains "🤖 Automated Fix Plan")
3. Check Method 1: thumbs up reactions
4. Check Method 2: approval keywords in comments
5. If approved → proceed
6. If not approved → post message, exit

Output: {approved: true, approver: "alice", method: "reaction"}
```

### Step 4: Create Branch Name

```bash
# Get issue title for slug
ISSUE_TITLE=$(gh issue view "$ISSUE_NUMBER" --json title --jq '.title')

# Create slug (lowercase, replace spaces with hyphens, remove special chars)
SLUG=$(echo "$ISSUE_TITLE" | tr '[:upper:]' '[:lower:]' | sed 's/[^a-z0-9]/-/g' | sed 's/--*/-/g' | cut -c1-30)

BRANCH_NAME="fix/issue-${ISSUE_NUMBER}-${SLUG}"

echo "🌿 Branch: $BRANCH_NAME"
```

### Step 5: Create Worktree

Use @superpowers:using-git-worktrees skill:

```markdown
Use superpowers:using-git-worktrees to create isolated workspace:

Arguments: "fix for issue #${ISSUE_NUMBER}"

This skill will:
1. Use .worktrees/ directory (already set up)
2. Create branch: $BRANCH_NAME
3. Set up worktree at .worktrees/$BRANCH_NAME
4. Run any project setup (npm install, etc.)
5. Verify clean baseline

If worktree creation fails → use @lib/error-handler template #4
```

### Step 6: Extract Plan from GitHub

```bash
# Get plan comment body
PLAN=$(gh issue view "$ISSUE_NUMBER" --json comments --jq '.comments[] | select(.body | contains("🤖 Automated Fix Plan")) | .body')

# Save to file for executing-plans skill
echo "$PLAN" > /tmp/issue-${ISSUE_NUMBER}-plan-extracted.md
```

### Step 7: Execute Implementation

Use @superpowers:executing-plans skill:

```markdown
Use superpowers:executing-plans to implement the fix:

Arguments: Path to plan file /tmp/issue-${ISSUE_NUMBER}-plan-extracted.md

This skill will:
1. Parse the plan into tasks
2. Execute task-by-task with checkpoints
3. Commit each file changed
4. Handle errors gracefully

Commit message format: "fix: <issue title> (fixes #<number>)"

If implementation fails:
- Partial work is committed
- Use @lib/error-handler template #5
- Create draft PR with status
```

### Step 8: Push Branch

```bash
echo "📤 Pushing branch to origin..."

cd .worktrees/$BRANCH_NAME
git push -u origin "$BRANCH_NAME"

if [ $? -ne 0 ]; then
  echo "❌ Failed to push branch"
  # Use @lib/error-handler template #6
  exit 1
fi
```

### Step 9: Create Pull Request

```bash
echo "📝 Creating pull request..."

# Get changes summary
FILES_CHANGED=$(git diff --name-only origin/main)

# Create PR body
PR_BODY=$(cat <<EOF
## 🤖 Automated Fix for Issue #${ISSUE_NUMBER}

Fixes #${ISSUE_NUMBER}

### Implementation Summary
This PR implements the automated fix based on the approved plan.

### Changes Made
$(echo "$FILES_CHANGED" | while read file; do echo "- \`$file\`: [description]"; done)

### Testing
- [ ] Unit tests pass
- [ ] Integration tests pass
- [ ] Manual verification completed

---
*This PR was automatically generated by the github-issue-handler skill.*
*Review the changes and approve when ready.*
EOF
)

# Create PR
PR_URL=$(gh pr create \
  --title "Fix: $ISSUE_TITLE" \
  --body "$PR_BODY" \
  --label "automated-fix" \
  --assignee "$(echo $ISSUE_JSON | jq -r '.author.login')" \
  2>&1)

if [ $? -eq 0 ]; then
  PR_NUMBER=$(echo "$PR_URL" | grep -oE '[0-9]+$')
  echo "✅ PR created: #$PR_NUMBER"
else
  echo "❌ PR creation failed: $PR_URL"
  # Use @lib/error-handler template #6
  exit 1
fi
```

### Step 10: Link PR to Issue

```bash
echo "🔗 Linking PR to issue..."

gh issue comment "$ISSUE_NUMBER" --body "$(cat <<EOF
✅ **PR Created!**

Pull request: #${PR_NUMBER}

The fix has been implemented based on the approved plan. Please review:
- Code changes
- Test coverage
- CI/CD results

Once reviewed, merge the PR to close this issue.

Branch: \`$BRANCH_NAME\`
EOF
)"

echo ""
echo "🎉 Success!"
echo "PR: https://github.com/${OWNER}/${REPO}/pull/${PR_NUMBER}"
echo "Issue: https://github.com/${OWNER}/${REPO}/issues/${ISSUE_NUMBER}"
```

### Step 11: Return to Main Workspace

```bash
cd ../..
echo ""
echo "💡 Worktree kept at: .worktrees/$BRANCH_NAME"
echo "To remove: git worktree remove .worktrees/$BRANCH_NAME"
```

## Error Handling

Uses @lib/error-handler for all failures:

- **No approval:** Template #3 (approval required)
- **Worktree fails:** Template #4 (worktree setup)
- **Implementation fails:** Template #5 (partial commit, draft PR)
- **PR creation fails:** Template #6 (branch pushed, manual PR)

## Complete Flow

```
/continue-issue 42
    ↓
Validate input
    ↓
Check approval (lib/approval-checker)
    ↓
    ├─ Not approved → Post message → Exit
    └─ Approved
        ↓
Create worktree (using-git-worktrees)
        ↓
Execute plan (executing-plans)
        ↓
Push branch
        ↓
Create PR
        ↓
Link to issue
        ↓
Success!
```

## Performance

- Approval check: ~5 seconds
- Worktree setup: ~10 seconds
- Implementation: 2-10 minutes (depends on complexity)
- PR creation: ~5 seconds
- Total: 3-15 minutes typically

## YAGNI Notes

**Not included:**
- Automatic merge after CI passes
- Multiple PR strategies (always creates one PR)
- Custom PR templates
- Automatic issue closure (GitHub does this)

Keep it simple: check approval, implement, create PR.
